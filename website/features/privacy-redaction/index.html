Local storage, privacy and redaction

Works without accounts

Recordings are written to your browser, not to a service we run. Data leaves only when you export it or use an integration you configured, and redaction reduces what is in it to begin with.

Storage
IndexedDB in your Chrome profile
Telemetry
None. No analytics and no developer-operated backend.
Policy
Privacy policy

What stays local

Sessions, screenshots, video, audio and drafts are stored in the browser’s IndexedDB. Deleting a session in the side panel deletes it there. Recording, annotating, markup and ZIP export never contact a server of ours, because there is none.

What leaves, and only when you set it up

IntegrationWhat is sentWhere
TranscriptionRecorded microphone audio, including spoken annotation commentsDeepgram, OpenAI or ElevenLabs
AI summaries and namesUp to 60,000 characters of text evidence; no mediaOpenAI, Anthropic, Google or your compatible endpoint
PublishingThe report, session data, transcripts and included mediaYour Cloudflare Pages project
GitHub issuesIssue title, summary and report linkThe repository you choose
Annotation vocabularyA bounded excerpt of visible headings, navigation and labels (no input values, editable or hidden content); then a short term listYour AI model; the term list to Deepgram or ElevenLabs

API keys and tokens live in extension storage, separate from recordings, and are never written into exports or published reports.

Redaction at capture time

Redaction is on by default and runs before data is written to storage, so the unmasked value is never saved. By default it masks:

  • Authorization, Cookie, Set-Cookie, X-API-Key, X-Auth-Token and proxy auth headers.
  • JSON and form fields whose names look like tokens, secrets, passwords, API keys, sessions, auth or credentials.
  • URL query parameters with names like those.
  • Password inputs.

You can add header names, body key patterns and URL parameter patterns, or turn redaction off for a session, in capture settings.

What redaction does not do

Redaction is pattern-based. It does not read screenshots, video or audio, and it cannot recognise personal data in ordinary fields, such as a customer name in a response body or an email typed into a form. Review evidence before publishing or attaching it anywhere, and use test accounts when you can.
