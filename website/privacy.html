Privacy Policy

Last updated: October 25, 2026

Session Recorder is a Chrome extension that records a session of you using a web app — interactions, network traffic, console logs, screenshots, voice narration, annotations, and files — and exports it as a local zip report intended for an LLM coding agent.

Recordings stay local by default. Optional transcription, AI summaries, and report publishing send data directly to services you configure.

Summary

  • Recordings stay local by default. Sessions are stored in your browser (IndexedDB) and exported as a zip file you save yourself. Session Recorder has no developer-operated backend or account system. We do not operate any server that receives your recordings.
  • Transcription is optional. If — and only if — you configure a transcription provider and API key, the audio you record is sent to that third-party provider to produce a text transcript. Publishing a report may also upload included audio to your Cloudflare account.

What the extension accesses

To record a session, the extension captures, on the tabs you are actively recording:

  • Network requests and responses (via chrome.debugger / CDP), including bodies and headers
  • Console logs, exceptions, and failed requests
  • Clicks, inputs, scrolls, keystrokes, and page navigations
  • Screenshots of the recorded tab
  • Microphone audio, when you start voice narration
  • Files you upload to the app or attach yourself

All of this is written to local browser storage. You can export a local ZIP or explicitly publish the selected report to your Cloudflare Pages project.

Redaction

Redaction is on by default. Before anything is written to storage, the extension masks authorization headers, token-like JSON and form fields, sensitive URL parameters, and password inputs. You can add rules or disable redaction per session on the options page.

Annotation dictation (optional)

Annotation comments use the recording microphone and your configured transcription provider. With the mic on, speech fills the active comment; its mic button starts or stops the recording microphone. The audio remains part of the session's voice recording. Deepgram and ElevenLabs provide live results; OpenAI uses audio segments. Typing does not start the microphone.

When an annotation is selected and an AI model is configured, a bounded excerpt of visible headings, navigation and interface labels is sent to that model to identify unusual vocabulary. Input values, editable fields and hidden content are excluded. The resulting short dictionary is sent to Deepgram or ElevenLabs to improve recognition. Page context and dictionaries are kept in memory, not saved with the session or published. No API keys are exposed to the recorded page. Provider fees apply; ElevenLabs charges extra for keyterm prompting. If extraction fails, ordinary transcription continues.

Third-party transcription (optional, off by default)

If you enter an API key on the options page, recorded audio is streamed or uploaded to the provider you selected in order to transcribe it:

  • Deepgram — deepgram.com/privacy
  • OpenAI — openai.com/policies/privacy-policy
  • ElevenLabs — elevenlabs.io/privacy

Your API key is stored locally in chrome.storage.local and is sent only to that provider. We do not receive, proxy, or store your key or your audio. Your use of a provider is governed by that provider's privacy policy and terms.

Optional publishing and AI summaries

Publishing uploads the selected report, session data, transcripts and included screenshots, recordings and files directly to your Cloudflare account. You configure who can sign in with Cloudflare Access. The deployed report also validates Access tokens before serving any file. Reports remain hosted until you delete them with Unpublish report or in Cloudflare. Deleting a local recording does not unpublish it.

Filing an issue with a configured model, or choosing Regenerate summary, sends up to 60,000 characters of text evidence directly to OpenAI, Anthropic, Google or the OpenAI-compatible endpoint you configure. With a configured model, stopping a recording also sends this bounded text evidence to generate its session-list title automatically. Media bytes are not sent to the model. Review the text first; provider terms and retention policies apply. Review the generated summary before sharing.

Filing a GitHub issue sends its title, summary and report link to GitHub. The extension creates it using your configured GitHub token. The summary follows repository visibility; Access protects the report, not the issue text. Drafts, deployment references and issue recovery markers are saved locally.

API keys remain in extension storage, separate from recordings, and are sent only to the configured service. They are never included in exports or published pages. Review screenshots, voice and attachments before publishing; redaction does not remove all sensitive information.

Data we collect

None. Session Recorder has no analytics, no telemetry, no ads, and no developer-operated backend. The developer does not receive any of your recordings, transcripts, keys, or usage data.

Data sharing and sale

We do not sell, share, or transfer any user data, because we never receive any.
