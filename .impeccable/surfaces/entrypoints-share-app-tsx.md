# Report first

Mode: Operate. QA and product teams reproduce bugs, annotate evidence, and file an actionable GitHub issue.

## Direction contract

THESIS: The recorded report is the workspace. Recording and filing stay obvious; technical configuration stays secondary.

WORLD: User-pinned Linear and Raycast: compact controls, sharp system typography, neutral white or charcoal surfaces, quiet divisions, restrained dark coral actions. Follow system appearance. Replace the rejected card-heavy UI, not a cosmetic polish of it.

FIRST VIEWPORT: A 180px navigation rail, 62px header with File issue, a readable central document, and a narrow metadata column. Title, summary, reproduction and evidence form one document. Technical details and publishing options are disclosures. Narrow screens keep the action header visible and move metadata below the document.

PATH: Record in the side panel → stop opens the full-page report → File issue generates a summary when configured, publishes behind Access, and creates the GitHub issue. Saved drafts, retries, screenshots, timeline and downloads remain available.

ANNOTATION: Match the supplied Codex reference. Click selects an element, drag selects any rectangle in either direction. Solid blue element outline, dashed blue region outline, numbered pins, anchored minimal comment pill with optional browser dictation and a check action. Enter submits, Shift+Enter adds a line, Escape backs out then exits. Screenshot markup remains separate.

FORM: Code-led. User selected `.impeccable/mocks/decision/report-first.html` on October 24, 2026. No image comp required. Interview pinned the conventional competitor direction; seed reference `seed:f93ac9e10585d01c`. The selected sketch is a composition reference with illustrative content, not production copy.

QUALITY BAR: No giant controls or nested cards. Readable contrast in both themes. Clear title and issue action. Evidence accessible without expanding technical data. Viewports 1440, 1226 and 390 plus narrow side panel. Preserve automatic summary, one-click issue flow and protected report. Support keyboard selection exit, anchored comment placement, reversed rectangle drag and errors without losing text.

FINISH: New system documentation and a fresh finish review are required. Earlier review evidence belongs to the rejected design and does not certify this replacement.
