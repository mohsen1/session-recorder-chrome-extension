# Design System: Session Recorder website

## Overview

**Creative North Star: "Report first"**

This is the scoped website extension of the established compact, clean, sharp Linear/Raycast direction. It covers `website/`, generated by `scripts/website/`, and merges the preceding website contract. The root `DESIGN.md`, `.impeccable/design.json` and approved extension composition remain authoritative for the application and are unchanged. This contract does not replace them.

The site uses readable document typography, neutral surfaces and flat rows to explain the path from a captured bug to an actionable GitHub issue. The larger reading ramp, wider public-page spacing, blue focus treatment and demonstration frame are website-specific exceptions. They must not be propagated to the compact extension UI. System light/dark appearance requires no theme control.

**Key Characteristics:**

- Flat sections and hairline-separated page lists, not card grids.
- Clear document hierarchy with a restrained coral installation action.
- Blue annotations, semantic status colors and neutral reading surfaces.
- Actual evidence or explicitly labeled synthetic illustration.

Extracted from `website/site.css`, `website/index.html` and the shared, feature and comparison generators on October 25, 2026. This records implementation evidence. The focused mobile-comparison repair received a ship verdict after valid recaptures; that verdict does not constitute a new whole-site or accessibility certification. The surface brief is [website](../../.impeccable/surfaces/website.md).

## Colors

The frontmatter records the CSS primitives. A `-dark` token replaces the corresponding unsuffixed role under `prefers-color-scheme: dark`; unspecified roles keep their light value.

### Primary

Coral `accent` is the solid action fill and `accent-ink` is its text. The separate `accent-text` is used for links and small action text; the dark counterpart preserves its reading role. `accent-hover` changes the solid action state. Coral is not a decorative section background.

### Secondary

Blue marks annotation geometry, keyboard focus and own-account availability tags. `blue-line` and `blue-tint` adapt to appearance. Numbered demo pins retain the deeper `annotation-pin` fill with white text in both themes. `ok` marks local availability and `danger` marks synthetic diagnostic errors.

### Neutral

`bg` carries the continuous canvas. `surface-2` distinguishes hover states, callouts, code, the footer and the annotated-page area; `surface-3` is an available stylesheet primitive, not a reason to add containers. `ink`, `ink-2` and `muted` separate headings, reading text and supporting metadata. `line` and `line-2` distinguish quiet rules from framed demonstrations and controls.

**The Accent Roles Rule.** Keep coral fill and readable coral text distinct, and preserve blue's functional annotation and focus roles.

## Typography

The website reuses the platform sans and mono stacks. Its larger reading hierarchy is scoped here, not an amendment to the extension's compact type ramp. The home headline is an observed implementation role using the incumbent stack; it is not a new global display-face recommendation.

The frontmatter maps the actual home headline, document h1, h2 title, h3 subheading, base body, document prose, button, table and code roles. Document ledes currently inherit the later paragraph rule (the prose role); the stylesheet’s earlier lede size does not win that cascade. Document prose is the default reading level; breadcrumbs and table headers use smaller supporting text (0.8125rem), and navigation and dates use 0.875rem. Primary buttons raise the button role to weight 600. Availability tags use 0.75rem at weight 600; sentence case remains the norm.

The home headline is limited to 15ch; its supporting paragraph is capped at 38rem. Home section headings scale from 1.5rem to 2rem, at weight 650 and line-height 1.15. Home introductory text uses 1.0625rem. Code and timestamped diagnostic evidence use mono; tables and numbered pins use tabular numerals. Headings balance their wrapping and paragraphs favor readable line breaks.

**The Reading Hierarchy Rule.** Keep the problem statement first, explanatory prose second and evidence, sources and metadata quieter without shrinking the main reading text to application-label size.

## Layout

The outer frame has a 70rem maximum width with the frontmatter gutter. Document pages limit prose to 42rem plus two gutters; the wider document variant allows 52rem plus gutters. Documents use 2.5rem top and 4rem bottom padding. Home hero and sections use fluid vertical spacing, while document h2 sections begin after 3rem.

Every page shares a skip link, sticky header, `main#content`, install band and footer. The header contains the brand, Features, Compare, Guides, Help, GitHub and Add to Chrome. At 760px and below the navigation moves into a horizontally scrollable second row; it stays available. The same breakpoint stacks the home workflow, account split and report illustration, replacing the illustration's vertical divider with a horizontal one. The install band wraps its actions naturally. At 860px and below the footer becomes two columns, with the about area spanning them.

Page-link rows pair title and summary in two columns and stack at 620px and below. Facts use a term/value grid, stacking at 520px and below. Comparison tables retain the ordinary three-column layout above 600px. At 600px and below each aspect becomes a full-width block: row heading, first product value, then second product value. Visible per-cell labels identify each value; the comparison hub uses the same stack for best fit and pricing. Column headers remain in the document through visual clipping, and duplicate cell labels are `aria-hidden`. Preserve the table and header markup; do not replace it with unlabeled prose or narrow squeezed columns. Other tables retain their overflow wrapper.

**The Quiet Structure Rule.** Establish hierarchy through reading width, space and selective hairlines; do not box every feature, paragraph or comparison aspect.

## Elevation & Depth

Content is flat. One two-layer shadow vocabulary is used by the report illustration and its anchored comment: light `0 1px 2px rgba(0, 0, 0, 0.04), 0 8px 24px rgba(0, 0, 0, 0.06)`; dark `0 1px 2px rgba(0, 0, 0, 0.4), 0 12px 32px rgba(0, 0, 0, 0.35)`. This website demonstration exception does not change the application's elevation contract. The sticky header uses a 92% background color mix and a saturate/blur backdrop, with a bottom hairline rather than a shadow.

## Shapes

Use the frontmatter radii for code/tags, navigation, controls, the anchored comment and the demo frame. Rules and table rows remain square and unboxed. The demonstration's numbered pins are circles; selected elements use solid outlines and selected regions dashed outlines. Its struck-through coupon chip is synthetic report content, not a reusable marketing pill pattern.

## Components

### Buttons and navigation

Primary actions use coral, white text and a matching border. Secondary actions use the canvas with the stronger neutral border. Regular buttons have a 2.5rem minimum height; the header variant has a 2rem minimum height, 0.75rem horizontal padding and 0.875rem type. Button rows wrap with 0.625rem gaps. Hover changes fill/border color over 0.15s ease; reduced motion disables transitions and animations.

Navigation is quiet text with a tinted hover fill. The current section uses stronger ink and weight 600 through `aria-current`. Keyboard focus uses a two-pixel blue outline with two-pixel offset. The skip link becomes visible on focus. These website focus and navigation behaviors are scoped exceptions to the application contract.

### Reading containers and page rows

Feature, guide and comparison indexes are hairline-separated title/summary links; only the title gains coral emphasis on hover. Definition blocks use top and bottom rules. Callouts use a quiet tonal background without a shadow. Code blocks may scroll horizontally. The contents list, breadcrumbs, related links and source list provide secondary navigation rather than competing hero elements.

Feature pages put the h1 before an availability tag, lede and facts list, followed by use, capture, limitations and related content. Local availability uses green; own-account availability uses blue. Comparison pages put the short answer before vendor context, the comparison table, pricing, workflow differences, limitations and cited sources. These are website templates, not product capability definitions.

### Comparison tables

Desktop table text uses the frontmatter table role, with quieter column headings and stronger row headings. Cells have bottom rules and 0.625rem vertical padding. The focusable, labeled wrapper supports overflow when needed. Mobile aspect groups have 1rem vertical padding and 0.875rem between product values; value labels use muted 0.8125rem text. Maintain the generator's per-cell labels for both the hub and each vendor page when adding or changing columns.

### Synthetic report illustration

The home figure is drawn in HTML with a visible caption identifying synthetic checkout data and explicitly saying it is not a screenshot of a real session. It contains a draft summary, numbered annotations, timestamped evidence, an annotated checkout and a File issue silhouette. The silhouette is illustrative, not a live action. The duplicate visual checkout is hidden from assistive technology; the textual annotations remain available.

The two-pane frame stacks at the shared narrow breakpoint. Its title truncates while the action silhouette stays visible. Secondary report metadata hides at that breakpoint; the repository segment hides at 420px and below. Preserve the explicit synthetic caption at all widths. Decorative dashboards, invented testimonials and implied customer evidence are not alternatives to actual evidence.

## Do's and Don'ts

### Do:

- Do follow system light and dark appearance and preserve semantic color roles.
- Do retain readable document text, visible keyboard focus, one h1 and logical heading order; verify contrast and responsive behavior during finish review.
- Do keep comparison values labeled when stacked and preserve their table headers.
- Do label synthetic imagery and keep real evidence proportionate and attributable.
- Do keep provider-cost caveats beside free claims and carry privacy limitations from the product source rather than inventing stronger guarantees.

### Don't:

- Don't export this website's larger type ramp, blue focus treatment or demo shadow into the extension's approved design contract.
- Don't introduce eyebrow labels, gradient text, fake testimonials, fabricated metrics or unsupported customer logos.
- Don't replace page rows with a card grid or squeeze comparison prose into unreadable mobile columns.
- Don't claim that all data always stays local, that redaction is complete, or that a visual extraction certifies the site as shipped.
